# ブログ執筆ガイド（hauoil.com/blog の正本）

小林顕人本人が書く時も、ちびあっきー（ChatGPT）や Claude Code が原稿を作る時も、この形式に従う。
仕組み側（ファイルの置き場・frontmatter の全項目・公開手順）は [README.md](README.md)。ここは「原稿の書き方」だけ。

## このブログは何か

- Instagram が「小林顕人を知る入口」、ブログは「考え方をより深く理解する場所」
- 「仕事で何を見ているのか」「なぜそう判断するのか」「会社をどう考えているのか」を蓄積する
- 読んだ経営者・マーケターが、自分の仕事に持ち帰れる内容にする
- 日記・ポエム・SEOのための量産記事にはしない
- 事実・数値・事例は出典（brain-hub / 本人の発言・記録）にあるものだけ。もっともらしい補足や推測を足さない

## 声

- 小林顕人の話し方をそのまま使う。「俺」「じゃん」「なんだよね」で書いてよい
- 話の「間」を短い改行で表現する。1行を短く切り、息をつく所で改行する
- 周り（CTA・著者表示・ナビ）は会社の言葉なので、本文の中で丁寧語に戻す必要はない

## 書式ルール（表示に直結する）

| ルール | 理由 |
|---|---|
| **1行改行は、ブログ上でもそのまま改行として表示される** | 話し方の「間」を文章表現として使うため。段落を分けたい時は空行を1つ入れる |
| **本文で H1（`#`）は使わない** | 記事タイトルが H1。本文に H1 があると構造化データ・AI検索の読みが崩れる |
| **大見出しは `##`（H2）** | 章の区切り。「そもそも」「見る順番」「まとめ」など |
| **小見出しは `###`（H3）** | 大見出しの配下。A〜D の型、パターン別の判断など |
| 章の間の `---`（区切り線）は使ってよい | 見出しの上の線とは重ならないよう表示側で処理済み |
| 太字は `**…**`。「」の外側に置く（`「**強調**」`） | `**「…」**` の形は太字にならないことがある |
| 表・箇条書き・番号リスト・引用・リンク・画像は普通の Markdown | 表の先頭列は折り返さない設計なので、短い語を置く |
| 画像は `public/blog/<slug>/` に置き、`![説明](/blog/<slug>/xxx.jpg)` | `cover.png` という名前は自動生成が使うので避ける |

## frontmatter（原稿の先頭に必ず付ける）

```yaml
---
title: 記事タイトル（32文字前後。アイキャッチにこの文字がそのまま入る）
description: 120文字前後。一覧の概要・検索結果・SNSシェアの説明文に共通で使う
date: 2026-01-01
category: marketing        # marketing / management / ai-systems / perspective
author: akihito
draft: true                # 原稿の段階では必ず true。公開判断は人間がして、外す
---
```

- タイトルはそのままアイキャッチ（1200×630）に流し込まれる。長すぎると小さくなるので 32 文字前後まで
- アイキャッチは自動生成。原稿側で用意しなくてよい。特別なビジュアルを使う記事だけ `cover: /blog/<slug>/xxx.jpg` を足す
- 関連記事は同カテゴリの最新が自動で出る。指定したい時だけ `related: [slug, slug]`

## 原稿を作る側（ちびあっきー / Claude Code）への約束

1. 新規原稿は `content/blog/<slug>.md` に **`draft: true`** で置く。公開はしない
2. slug は半角英小文字・数字・ハイフンのみ。日本語タイトルをそのまま使わない
3. 元記録に無いことは書かない。足したくなったら「ここは記録に無い」と本人に返す
4. 既存記事を直す時は `updated: YYYY-MM-DD` を今日にする
5. 出来たら `npm run dev` で `/blog/<slug>` を開いて、改行と見出しの見え方を確認する
